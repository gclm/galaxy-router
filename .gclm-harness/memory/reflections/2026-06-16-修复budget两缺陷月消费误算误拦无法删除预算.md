# budget 月消费误算 + 无法删除 反思

## Expected vs Actual
- Expected: 月预算只按当月消费判断;清空预算能删除
- Actual: monthly_cost 算全部历史(无当月过滤)→ 误拦;清空不附 budget 字段 → 删不掉

## Root Cause
1. `check_budget` 的 monthly 查询漏了当月 WHERE(`SUM(cost)` 无时间范围),而 daily 查询有 `date('now')` 过滤——两个查询风格不对称,review 没注意到这个不一致。
2. `handleSubmit` 用 `>0` 守卫决定是否附 budget,无法表达"清空(=0)"意图。

## Why Not Caught Earlier
- monthly/daily 查询风格不对称,没在 review 时对齐。
- 前端无测试框架,budget 附带逻辑没覆盖"清空"场景。
- chrome-mcp `fill` 对 React 受控组件无效,导致 E2E"复现"是假象(没真正清空 state),差点误判根因。

## Next Time
- 时间范围查询统一走 helper(`range_utc_*`),裸列 `created_at` 比较——既命中索引又避免漏过滤。
- "清空=删除"这类语义,提交数据要能区分"未设"vs"清空"(显式附 0),别用"不附字段"偷懒。
- 测 React 受控表单用 `evaluate_script` valueTracker,别信 `fill`。
