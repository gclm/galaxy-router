# 项目文档规范

## 文档体系结构

```
.gclm-harness/
├── decisions/          # 决策层 — 确定后基本不变
│   ├── architecture/   # 架构决策
│   ├── requirements/   # 需求愿景
│   └── attention.md    # 项目注意事项
├── solutions/          # 方案层 — 随迭代演进
│   ├── features/       # 功能方案
│   ├── optimizations/  # 优化方案
│   └── roadmap.md      # 开发计划
├── operations/         # 运维层 — 持续积累
│   ├── sop/            # 排查手册
│   └── issues/         # 问题记录
└── reference/          # 参考层 — 静态资料
    ├── analyses/       # 竞品分析
    └── conventions/    # 开发规范
```

## 文档归属判断

遇到新文档时，按以下规则判断归属：

| 文档内容 | 归属目录 | 判断依据 |
|----------|----------|----------|
| 为什么选择这个技术方案 | `decisions/` | 确定后基本不变 |
| 项目愿景和需求边界 | `decisions/` | 确定后基本不变 |
| 功能怎么实现 | `solutions/` | 需要实施的工作 |
| 优化方案设计 | `solutions/` | 需要实施的工作 |
| 开发任务和计划 | `solutions/roadmap.md` | 需要实施的工作 |
| 出了问题怎么排查 | `operations/sop/` | 运维排查流程 |
| 踩过的坑和复盘 | `operations/issues/` | 问题记录 |
| 竞品分析报告 | `reference/analyses/` | 静态参考资料 |
| 开发编码规范 | `reference/conventions/` | 静态参考资料 |

## 方案文档模板

写方案时使用以下模板：

```markdown
# {标题}

## 目标
要解决什么问题

## 方案
技术设计、接口、流程

## 实施清单
- [ ] 步骤1
- [ ] 步骤2
- [ ] 步骤3

## 验收标准
怎么算完成
```

## 决策文档模板

```markdown
# {标题}

## 背景
为什么需要做这个决策

## 决策
我们选择了什么

## 理由
为什么这样选

## 约束
这个决策带来的限制
```

## 注意事项

1. **不要混淆决策和方案**：决策是已确定的事实，方案是待实施的工作
2. **方案包含计划**：不需要单独写计划文档，在方案的"实施清单"段落中体现
3. **保持文档同步**：方案实施完成后，更新清单状态
4. **问题及时记录**：遇到问题及时记录到 `operations/issues/`，避免遗忘
